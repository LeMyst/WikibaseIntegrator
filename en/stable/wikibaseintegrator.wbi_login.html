reauthenticate()

Recover from a session that the server has invalidated (e.g. MediaWiki returning ‘assertuserfailed’/’assertbotfailed’/’notloggedin’ on an otherwise well-formed request, see #902).

Simply asking for a new CSRF token via generate_edit_credentials() cannot resurrect a session the server has already dropped, since that call is itself authenticated by the same (now invalid) session cookies. This default implementation is only adequate for auth methods where generate_edit_credentials() actually re-establishes the underlying credentials (OAuth2, which refreshes its access token first) or where authentication is per-request rather than session-based (OAuth1). Login and Clientlogin override this to redo the full username/password login.

Return type:

class wikibaseintegrator.wbi_login.WCQSAuth(oauth_cookie)[source]

Bases: AuthBase

Authentication for the Wikimedia Commons Query Service (WCQS, https://commons-query.wikimedia.org/), the SPARQL endpoint of Structured Data on Commons, e.g. to use the fast run mode with MediaInfo entities.

WCQS authenticates with the long-lived ‘wcqsOauth’ cookie. There is no API to get it: copy it from a web browser logged in to WCQS, see https://commons.wikimedia.org/wiki/Commons:SPARQL_query_service/API_endpoint. WCQS answers with a redirect setting a short-lived ‘wcqsSession’ cookie, which the HTTP session of WikibaseIntegrator keeps for the next queries.

To authenticate every query, including the ones of the fast run mode:

wbi_config['SPARQL_ENDPOINT_URL'] = 'https://commons-query.wikimedia.org/sparql'
wbi_config['SPARQL_AUTH'] = WCQSAuth('<wcqsOauth cookie>')

An invalid or revoked cookie raises a WCQSAuthenticationError.
