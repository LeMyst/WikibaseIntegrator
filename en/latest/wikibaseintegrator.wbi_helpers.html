wikibaseintegrator.wbi_helpers.check_constraints(entity_id=None, claim_id=None, status=None, allow_anonymous=True, **kwargs)[source]

Check the constraint violations of one or more entities or claims, using the target Wikibase instance’s own constraint checker (the wbcheckconstraints API module provided by the WikibaseQualityConstraints extension).

This relies entirely on the constraints configured on the Wikibase instance being queried (e.g. on Wikidata itself), rather than on a hardcoded or Wikidata-specific set of rules, so it works the same way against any Wikibase instance that has the extension installed. If the extension isn’t installed, the underlying API call will fail with a MWApiError.

Parameters:

  • entity_id (str | list[str] | None) – One or more entity IDs (item, property, lexeme, etc.) whose claims should be checked.

  • claim_id (str | list[str] | None) – One or more claim GUIDs to check, instead of checking whole entities.

  • status (list[str] | None) – Only return results with one of these statuses, e.g. ['violation']. By default, the API returns every status.

  • allow_anonymous (bool) – Allow anonymous interaction with the MediaWiki API. ‘True’ by default since this is a read-only action.

  • kwargs (Any) – Extra parameters for mediawiki_api_call_helper()

Return type:

dict

Returns:

The data returned by the API as a dictionary

wikibaseintegrator.wbi_helpers.check_wikibase(mediawiki_api_url=None, sparql_endpoint_url=None, wikibase_url=None, check_sparql=True, login=None, **kwargs)[source]

Check the features of a Wikibase instance: the MediaWiki version, the installed extensions, the entity types and the datatypes it supports, and whether the SPARQL endpoint answers. It also checks the configuration of WikibaseIntegrator: a ‘WIKIBASE_URL’ not matching the concept URIs of the instance breaks the SPARQL queries built by WikibaseIntegrator (fast run mode, …). The problems found are listed in the ‘problems’ attribute.

Example: print(check_wikibase())

Parameters:

  • mediawiki_api_url (str | None) – The URL to the MediaWiki API. Default config[‘MEDIAWIKI_API_URL’].

  • sparql_endpoint_url (str | None) – The URL to the SPARQL endpoint. Default config[‘SPARQL_ENDPOINT_URL’].

  • wikibase_url (str | None) – The Wikibase URL compared with the concept URIs of the instance. Default config[‘WIKIBASE_URL’].

  • check_sparql (bool) – Send a test query to the SPARQL endpoint.

  • login (_Login | None) – A login instance, to check a private instance.

  • kwargs (Any) – More arguments for mediawiki_api_call_helper()

wikibaseintegrator.wbi_helpers.create_redirect(from_id, to_id, login=None, is_bot=False, **kwargs)[source]

A static method to turn an item into a redirect to another item, with the wbcreateredirect API.

The source item must be empty, deleted or already a redirect (to change its target, e.g. to fix a double redirect). To combine two items which both have content, use merge_items(), which creates the redirect itself. Wikibase only supports redirects between items with this API, and it doesn’t accept a summary or change tags.

Parameters:

  • from_id (str) – The ID of the item to turn into a redirect. This parameter is required.

  • to_id (str) – The ID of the item to redirect to. It must exist and not be a redirect itself. This parameter is required.

  • login (_Login | None) – A wbi_login.Login instance

  • is_bot (bool) – Mark this edit as bot.

  • kwargs (Any)

Return type:

dict

Returns:

The API response, with the ID of the target item in the ‘redirect’ key.

wikibaseintegrator.wbi_helpers.execute_sparql_query(query, prefix=None, endpoint=None, user_agent=None, max_retries=None, retry_after=60, auth=None, headers=None)[source]

Static method which can be used to execute any SPARQL query

Server errors (HTTP 5xx), throttling (HTTP 429, after the delay asked by the Query Service), request timeouts (HTTP 408), connection errors and responses cut before their end are retried by wbi_backoff, up to config[‘BACKOFF_MAX_TRIES’] times. If the Query Service still fails after that, the last exception (e.g. requests.HTTPError) is raised. The other client errors (e.g. HTTP 400 for a malformed query) are raised at once.

Parameters:

  • prefix (str | None) – The URI prefixes required for an endpoint, default is the Wikidata specific prefixes

  • query (str) – The actual SPARQL query string

  • endpoint (str | None) – The URL string for the SPARQL endpoint. Default is the URL for the Wikidata SPARQL endpoint

  • user_agent (str | None) – Set a user agent string for the HTTP header to let the Query Service know who you are.

  • max_retries (int | None) – Deprecated and ignored, use config[‘BACKOFF_MAX_TRIES’] instead.

  • retry_after (int) – The number of seconds to wait after a HTTP 429 (Too Many Requests) response without a Retry-After header.

  • auth (tuple[str, str] | AuthBase | None) – Authentication for a protected SPARQL endpoint: a (username, password) tuple for HTTP Basic auth or any requests.auth.AuthBase instance. Default is config[‘SPARQL_AUTH’].

  • headers (dict[str, str] | None) – Additional HTTP headers sent with the query (e.g. {‘Authorization’: ‘Bearer <token>’}). They override the default ones.

Return type:

dict[str, dict]

Returns:

The results of the query are returned in JSON format

Raises:

requests.HTTPError – If the Query Service returns an HTTP error, after the retries for the transient ones are exhausted

wikibaseintegrator.wbi_helpers.generate_entity_instances(entities, allow_anonymous=True, **kwargs)[source]

A method which allows for retrieval of a list of Wikidata entities. The method generates a list of tuples where the first value in the tuple is the entity’s ID, whereas the second is the new instance of a subclass of BaseEntity containing all the data of the entity. This is most useful for mass retrieval of entities. The entities are requested by batches of 50, the limit of wbgetentities.

Parameters:

  • entities (str | list[str]) – A list of IDs. Item, Property, Lexeme or MediaInfo.

  • allow_anonymous (bool) – Allow an anonymous request to the MediaWiki API. Enabled by default.

  • kwargs (Any)

Return type:

list[tuple[str, BaseEntity]]

Returns:

A list of tuples, first value in the tuple is the entity’s ID, second value is the instance of a subclass of BaseEntity with the corresponding entity data.

Raises:

  • NonExistentEntityError – If an ID doesn’t exist on the Wikibase instance

  • MissingEntityException – If an entity is missing, e.g. deleted

  • ValueError – If an entity has a type that no subclass of BaseEntity implements

wikibaseintegrator.wbi_helpers.mediawiki_api_call(method, mediawiki_api_url=None, session=None, login=None, max_retries=20, retry_after=60, **kwargs)[source]

A function to call the MediaWiki API.

Parameters:

  • method (str) – ‘GET’ or ‘POST’

  • mediawiki_api_url (str | None)

  • session (Session | None) – If a session is passed, it will be used. Otherwise, the current thread’s default session is used

  • login (_Login | None) – If provided and the API reports that the session is no longer authenticated (see SESSION_LOST_ERROR_CODES), it is used to fully re-authenticate before retrying, once per call.

  • max_retries (int) – The maximum number of tries of the request. The instance asking to slow down (maxlag, rate limiting, HTTP 429, readonly mode) is waited for up to this number of tries. The failures (connection errors, HTTP 5xx, and read timeouts of the READ_ONLY_ACTIONS) are tried at most config[‘BACKOFF_MAX_TRIES’] times, with a wait doubling from 1 second, like wbi_backoff.

  • retry_after (int) – The maximum number of seconds to wait between two tries after a failure or a maxlag, and the wait when the instance doesn’t say how long to wait (rate limiting without Retry-After, readonly mode)

  • kwargs (Any) – Any additional keyword arguments to pass to requests.request

Return type:

dict

wikibaseintegrator.wbi_helpers.set_claim(claim, entity_id=None, index=None, baserevid=None, summary=None, tags=None, ignore_duplicate_mainsnak=False, login=None, is_bot=False, **kwargs)[source]

Create or replace a single statement, with its qualifiers and references, with the wbsetclaim API.

Unlike a write of the whole entity, only this statement is sent: the entity doesn’t need to be loaded first, and the edit doesn’t conflict with the edits of the other statements. A claim with an ID replaces the statement with this ID. A claim without an ID is added to the entity given by entity_id, and the ID generated for it is set on the claim once the edit is saved.

Parameters:

  • claim (Claim) – The claim to write, e.g. a datatype instance like String(prop_nr=’P31’, value=’foo’). It can’t be marked as removed, use remove_claims() instead.

  • entity_id (str | None) – The ID of the entity of a new claim (without ID). Optional for a claim with an ID, which already contains the ID of its entity.

  • index (int | None) – The position to move the statement to in the list of statements of the entity.

  • baserevid (int | None) – The numeric identifier for the revision to base the modification on. This is used for detecting conflicts during save.

  • summary (str | None) – Summary for the edit. Will be prepended by an automatically generated comment.

  • tags (list[str] | None) – Change tags to apply to the revision.

  • ignore_duplicate_mainsnak (bool) – Don’t save the statement if the entity already has a statement with the same main snak. The API then answers with a warning instead of the saved statement.

  • login (_Login | None) – A wbi_login.Login instance

  • is_bot (bool) – Mark this edit as bot.

  • kwargs (Any) – More arguments for mediawiki_api_call_helper() and Python requests

Return type:

dict

Returns:

The API response, with the saved statement in the ‘claim’ key.

Raises:

  • ValueError – if the claim is marked as removed, if a new claim has no entity_id, or if the ID of the claim doesn’t match entity_id

  • EmptyValueError – if a snak of the claim has no value
